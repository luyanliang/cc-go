# Spec Delta

## Purpose

输入区升级：语音听写、输入草稿按会话持久化与斜杠面板增强，降低移动端输入摩擦。

## ADDED Requirements

### Requirement: 语音听写

输入框 SHALL 提供语音输入入口：草稿为空时发送键位置呈现语音入口，启动后进入听写状态——识别文本实时显示在输入框、有音量反馈、提供停止操作；停止后识别文本落入草稿等待用户编辑或发送。语音识别不可用（无引擎/无权限）时 SHALL 回退为普通发送键并给出可理解的原因，MUST NOT 影响文字输入。

#### Scenario: 听写落入草稿
- **WHEN** 用户启动听写说一段话后点停止
- **THEN** 识别文本出现在输入框草稿中，可继续编辑或发送

#### Scenario: 无语音引擎回退
- **WHEN** 设备不支持语音识别或用户拒绝麦克风权限
- **THEN** 入口回退为普通发送键，并提示原因；文字输入不受影响

### Requirement: 草稿按会话持久化

聊天页的输入草稿（含引用上下文）SHALL 按会话持久化：离开聊天页再返回、切换到其他会话再切回后，草稿 MUST 恢复。消息发送成功后草稿 MUST 清空。持久化 MUST 随会话隔离，不得串到其他会话。

#### Scenario: 切走再回草稿保留
- **WHEN** 用户在会话 A 输入半段文字后切到会话 B 再切回 A
- **THEN** 会话 A 的草稿原样恢复，会话 B 显示自己的草稿

#### Scenario: 发送后清空
- **WHEN** 用户发送一条消息
- **THEN** 该会话草稿清空

### Requirement: 斜杠面板增强

斜杠指令面板 SHALL 在指令名旁显示一句中文说明；输入指令名过程中候选列表 SHALL 标示"发送将选中该指令"的确认语义。现有补全行为（选中补全为 `/name `、出现空格收起）MUST 保留。

#### Scenario: 候选带说明
- **WHEN** 用户输入 `/` 触发面板
- **THEN** 每个候选指令显示名称与一句说明

#### Scenario: 既有补全行为保持
- **WHEN** 用户点击某候选指令
- **THEN** 输入框补全为 `/name `，继续输入空格后面板收起
