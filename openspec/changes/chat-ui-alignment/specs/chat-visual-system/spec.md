# Spec Delta

## Purpose

建立聊天窗口的视觉体系：app 级主题 token 层（调色、玻璃表面、圆角、动效、共享视觉件）与聊天页 chrome（玻璃胶囊顶栏、状态行、内容滚动到玻璃之下、空态），使聊天窗口从 M3 默认形态升级为一致的玻璃拟态观感。

## ADDED Requirements

### Requirement: 主题 token 层

App SHALL 建立独立于 `ColorScheme.fromSeed` 的主题 token 层：手工调色板（明暗两套，强调色对比度同档）、玻璃表面分级（至少区分 chrome / sheet / card 三级，每级有明确的模糊、半透明填充、描边与投影规格）、连续曲率圆角规格与动效时长 token（反馈 ≤160ms、结构 240–340ms、环境 ≥2s 三档）。聊天窗口的所有新界面 MUST 使用该 token 层而非散落的硬编码样式；token 层本身 MUST NOT 依赖聊天窗口的 widget。

#### Scenario: 明暗主题下的一致观感
- **WHEN** 系统切换深色/浅色主题并打开聊天窗口
- **THEN** 玻璃顶栏、输入条、卡片与胶囊均按对应主题的 token 渲染，无硬编码颜色残留导致的对比度失效

#### Scenario: token 层无聊天依赖
- **WHEN** 在 headless 测试中导入主题 token 层
- **THEN** 不引入任何 `lib/ui/chat/` 的依赖

### Requirement: 玻璃胶囊顶栏

聊天页顶栏 SHALL 由浮动玻璃胶囊组构成而非整条 AppBar 色带：会话入口键、标题胶囊、模型胶囊（点击打开既有模型选择弹层）、新对话键。当总宽超出可用空间时 SHALL 按固定顺序逐级让出——先收缩次要信息（如模型胶囊的附加标注）、再截短标题、再截短模型名，任何一级都 MUST 保留模型胶囊与新对话键本身。

#### Scenario: 宽屏完整展示
- **WHEN** 屏幕宽度足够容纳全部胶囊
- **THEN** 顶栏完整显示标题、模型胶囊与各功能键

#### Scenario: 窄屏逐级让出
- **WHEN** 屏幕宽度不足以容纳全部胶囊
- **THEN** 按预定义顺序收缩内容，模型入口与新对话键始终可见，无溢出告警

### Requirement: 状态行

顶栏 SHALL 在标题胶囊下方以"状态点 + 一句人话"展示会话阶段（如"已就绪 / 生成中 / 等待权限"）。状态 MUST NOT 仅靠颜色区分，MUST 同时有文字。

#### Scenario: 阶段切换可感知
- **WHEN** 会话从空闲转为运行中再进入等待权限
- **THEN** 状态行文字随之更新，且每次都伴随状态点变化，不依赖颜色单独表达

### Requirement: 内容滚动到玻璃之下

消息列表 SHALL 在玻璃顶栏与输入条之下滚动（内容从半透明 chrome 下穿过），chrome 的背景遮罩 SHALL 随内容滚动平滑渐隐，滚动内容 MUST NOT 被 chrome 生硬裁切。

#### Scenario: 滚动穿过顶栏
- **WHEN** 用户向上滚动消息列表
- **THEN** 消息内容在顶栏玻璃之下渐隐穿出，顶栏胶囊保持可读

### Requirement: 空态

会话无任何转录条目时，聊天页 SHALL 展示升级后的空态：时段问候语与副标题居中偏上，下方提供会话内可操作的建议入口（如建议提示词卡片，点击填入输入框而非直接发送）。加载中的空态 MUST 与"真正为空"的空态可区分。

#### Scenario: 新会话空态
- **WHEN** 打开一个无历史的新会话
- **THEN** 显示问候语与建议入口，点击建议卡片将内容填入输入框等待用户确认发送

#### Scenario: 加载中不误显空态
- **WHEN** 打开一个有历史但快照尚未到达的会话
- **THEN** 显示加载指示而非空态问候
