# Spec Delta

## Purpose

发现、回放与接管 Claude Code 的会话历史（含终端创建的会话），以及已接管会话的外部写入同步。

## ADDED Requirements

### Requirement: 外部会话发现
对每个已注册且可用的项目目录，daemon SHALL 枚举 Claude Code 会话存储（`~/.claude/projects/<编码路径>/`）中属于该目录的会话文件，返回每项的会话 id、最后活动时间、标题（取首条用户消息截断，缺失时回退为时间表示）与消息条数，按最后活动时间倒序。已被 cc-go 管理的会话 MUST 被识别并标记，与外部会话区分。

#### Scenario: 列出终端创建的会话
- **WHEN** 已认证客户端枚举某项目目录的会话历史
- **THEN** 返回该目录下全部 Claude Code 会话的元信息，按最后活动时间倒序，包含从未由 cc-go 创建的会话

#### Scenario: 区分已托管会话
- **WHEN** 枚举结果中存在已被 cc-go 创建或导入的会话
- **THEN** 该会话带有已托管标记，客户端可将其与外部会话区分呈现

### Requirement: 历史回放
daemon SHALL 将指定会话的转录文件转换为现有转录条目模型（用户/助手/工具/提示四类）并分页返回；回放 MUST 为只读操作，不修改原文件、不创建会话。转录文件中的 Claude Code 内部记录（文件快照、队列操作等非对话内容）MUST NOT 出现在回放结果中；工具调用与其结果 SHALL 以配对后的完整形态呈现。

#### Scenario: 回放终端会话
- **WHEN** 客户端请求某外部会话的历史且该转录文件有效
- **THEN** 返回按时间序的条目列表，与 cc-go 自有会话的快照格式一致，可直接用现有渲染逻辑展示

#### Scenario: 长会话分页
- **WHEN** 会话条目数超过单页上限
- **THEN** 客户端可按页继续获取更早的条目

#### Scenario: 无效会话文件
- **WHEN** 请求的会话文件不存在或内容无法解析
- **THEN** 返回可理解的错误，不影响其他会话的发现与回放

### Requirement: 接管续聊
用户 SHALL 能把一个外部会话导入为 cc-go 会话；导入后新会话 MUST 从该 Claude 会话的既有上下文继续（恢复语义），且手机端聊天页 MUST 展示该会话的完整历史条目。导入 MUST NOT 修改或移动原转录文件。重复导入同一 Claude 会话 SHALL 幂等（返回已存在的 cc-go 会话而非新建）。

#### Scenario: 接管并继续对话
- **WHEN** 用户在某外部会话的历史页选择接管并发送第一条消息
- **THEN** Claude 基于该会话的原有上下文作答，聊天页完整显示历史与新增条目

#### Scenario: 重复接管幂等
- **WHEN** 用户对同一 Claude 会话再次发起导入
- **THEN** 返回此前导入所得的 cc-go 会话，不产生重复会话

#### Scenario: 接管后原文件不受影响
- **WHEN** 导入完成后检查 Claude Code 会话存储
- **THEN** 原转录文件仍存在且内容未被 cc-go 修改

### Requirement: 只读历史浏览
手机端 SHALL 提供外部会话的历史浏览视图：呈现回放条目、标识只读状态；未接管时 MUST NOT 提供发送入口，并提供显式的接管入口。

#### Scenario: 只读浏览
- **WHEN** 用户打开一个未接管的外部会话
- **THEN** 聊天页展示历史条目并标识只读，输入框不可用，页面提供接管操作

### Requirement: 已接管会话的外部写入同步
已接管会话的转录文件被其他进程（如终端恢复同一会话）追加时，daemon SHALL 在数秒级的轮询间隔内把新追加的对话条目并入该会话的手机转录。daemon 自身产生的内容 MUST NOT 被重复并入（去重）。外部写入中正在生成的部分内容 SHALL 在完整落盘后再并入。

#### Scenario: 终端并行输入同步
- **WHEN** 已接管会话在终端中被恢复并继续对话
- **THEN** 手机端转录在数秒内出现终端侧的新用户消息与回复

#### Scenario: 自有消息不重复
- **WHEN** 手机端发送的消息经 Claude 处理后也被写入转录文件
- **THEN** 该消息在手机转录中只出现一次
